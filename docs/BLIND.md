# 블라인드 재측정 (2026-10-28)

말투를 바꾼 진술 10건(`data/natural`)은 진술과 정답을 같은 모델이 썼기 때문에 결과가 실제보다 좋게 나올 수 있었습니다. 그래서 진술을 쓰는 쪽, 정답을 정하는 쪽, 추출하는 쪽을 서로 나눠 한 번 더 쟀습니다.

## 어떻게 나눴나

| 역할 | 누가 | 볼 수 있던 것 |
|---|---|---|
| 정답 | `tools/make_blind.py` | 장면 설명 20개와 도표 규칙. 코드로 기대 경로, 도표, 규칙, 일정을 정함 |
| 진술 | Claude Haiku 하위 에이전트 | 장면 설명만. 도표 번호, 규칙, 정답은 보지 못함 |
| 추출 | Claude Sonnet 하위 에이전트 | 스킬 문서(`SKILL.md`)와 사례 파일만. `expect.json`, 진술 원본, 규칙 코드는 열지 못하게 함 |

진술 20건은 사람이 한 번 읽고 장면 설명과 어긋나는 곳만 고쳤습니다. B001 장면의 "신호 없는 구간"이 신호 없는 교차로로 읽힐 수 있어 "퇴근길에"로 바꿨습니다. 진술에는 "억울합니다", "정신이 없었어요" 같은 감정 표현 줄이 덧붙었는데, 실제 진술에 가까워서 그대로 뒀습니다.

## 결과

자세한 표는 [reports/compare-blind.md](../reports/compare-blind.md)와 [reports/scorecard.md](../reports/scorecard.md)에 있습니다.

| 지표 | 낱말 규칙(`cues`) | AI 추출(`skill`) |
|---|---|---|
| 심사 경로 일치 | 6/20 | 18/20 |
| 사람이 봐야 할 사고를 자동 처리 후보로 낸 건 | 0 | 0 |
| 자동 처리 후보로 남긴 건(기대 14건 중) | 0 | 12 |
| 과실 에이전트 등급 | 초급 | 중급(17/20) |

말투를 바꾼 10건에서는 AI 추출이 10/10, 과실 에이전트가 고급이었습니다. 블라인드에서는 18/20, 중급으로 내려갔습니다. 앞의 10/10이 후했다는 뜻이고, 이 숫자를 더 믿을 만한 값으로 봅니다.

## 틀린 2건

| 사례 | 무엇이 빠졌나 | 결과 |
|---|---|---|
| B002 | 고객 진술에 상대 차가 무엇을 하고 있었는지가 없음("앞차 뒤를 제가 박았습니다"만 있음) | 상대 진행이 비어 도표를 하나로 정하지 못함(R06), 사람 심사 |
| B004 | 고객 진술에 뒤차의 진행이 없음("뒷문 쪽을 받더라고요"만 있음) | 같은 까닭으로 사람 심사 |

두 건 모두 추출기가 짐작해서 채우지 않고 비워 둔 결과입니다. 자동 처리 후보를 놓친 것이지, 틀린 결과가 고객에게 나간 것은 아닙니다. 상대 진술에는 같은 정보가 있었으므로, 한쪽 진술의 빈칸을 다른 쪽 진술로 메우는 규칙을 넣으면 줄일 수 있습니다. 다만 그 규칙은 두 진술이 서로 다를 때 어느 쪽을 믿을지를 정해야 해서 이번에는 넣지 않았습니다.

## 추출 에이전트가 애매하다고 적은 곳

- B006, B020의 차로 감소 구간은 허용 장소 낱말에 딱 맞는 것이 없어 합류지점으로 적었습니다.
- "뒤에서 따라오던 차가"를 직진으로 읽었습니다. 근거가 약하다고 보면 비워야 하고, 그러면 자동 처리 후보가 더 줄어듭니다.
- B014는 두 진술이 서로 모순되어 각자 진술대로 적었고, 규칙 R05(진술 불일치)로 사람 심사에 갔습니다.

## 남은 한계

- 진술을 쓴 Haiku와 추출한 Sonnet은 같은 회사의 모델입니다. 사람이 쓴 진술로 잰 값이 아닙니다.
- 장면 설명과 정답은 이 저장소가 만든 것이라, 장면 고르기에 치우침이 있을 수 있습니다.
- 20건은 비율을 말하기에 적은 수입니다.
